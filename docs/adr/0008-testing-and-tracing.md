# 0008 Testing and tracing

Status: accepted

- **Instruction vectors** (`crates/ppc-lift/tests/vectors.rs`, data in `vectors.bin`, generated by `tools/gen_vectors.py`): small programs with inputs and expected outputs. Integer, CR, branch-condition, load/store and standard FP programs are executed on Unicorn (QEMU, PowerPC 750CL), an oracle that shares no code with this project; Gekko-only instructions (paired singles, quantized load/store) use an independent model in the script. Each program is lifted, compiled with clang and run; all GPRs, ps0/ps1, CR, LR, CTR and a 128-byte memory window are compared (XER via `mfxer r0`, FPSCR via `mcrfs`).
- Known oracle gaps, handled in the script: Unicorn does not propagate raw XER/FPSCR writes (set with instructions instead), leaves the upper word of `fctiw`/`mffs` undefined and returns 0x80000000 on positive `fctiw` overflow (expected values follow the architecture and Gekko instead), and its division results for /0 are arbitrary (those operands are not generated).
- **Helper tests** (`runtime/tests/ppc_test.cpp`, `ctest`): estimate accuracy and specials for `fres`/`frsqrte`, `stfs`/`lfs` conversions, NaN rules.
- Not covered by an oracle: `fres`/`frsqrte` exact values (tables from Dolphin), FPSCR status flags, non-nearest rounding for arithmetic, paired-single behaviour on real hardware. Trace and screenshot comparison with Dolphin (M4.1) remains the end-to-end check.
- CI sets `FEPOR_REQUIRE_CLANG=1`; locally the clang-based tests skip when clang++ is missing. Regenerating vectors needs `pip install unicorn` (see the script's docstring).
- **Tracing** (`FEPOR_TRACE=hw,calls,irq,gx,di,audio,tex,...`, comma separated; `FEPOR_WATCH=<hex function addresses>` prints the arguments at every entry; `FEPOR_GX_LOG=<n>` lists every GX command of one frame; frame, texture and audio dumps): readable logs of what the recomp does. They are not in Dolphin's trace format: the two emulators do not share a level at which calls could be matched one to one, so they are compared by what they show and play.
- **Frame comparison with Dolphin** (`tools/compare-frames.py`, M4.1): `tools/dolphin-run.sh --iso <disc> --dump-frames --user /tmp/dol -- wait:30` makes Dolphin write `/tmp/dol/Dump/Frames/framedump_N.png`; the game run with `FEPOR_HEADLESS=1 FEPOR_NO_AUDIO=1 FEPOR_FPS_MULT=1 FEPOR_RES=1 FEPOR_DUMP_FRAMES=dir FEPOR_DUMP_EVERY=1` writes one PNG per presented frame; `compare-frames.py --recomp dir --dolphin /tmp/dol/Dump/Frames --first N --out worst/` matches the recomp frames to Dolphin's by dynamic time warping (the runs do not keep step), prints the PSNR of each match and saves the worst ones side by side with their difference. First result, the first 1000 frames with no input: the "Press any button to continue" health screen matches at a median 34.8 dB (the 30 dB frames are the blinking prompt), the first black frames are identical (99 dB). The one difference it showed, checked by looking at Dolphin's frames: Dolphin opens on the EU "60Hz mode / 50Hz mode" prompt, and with no input picks 50 Hz after about 12 s ("Screen display has been set to 50Hz mode") before the health screen; the recomp starts on the health screen at once and runs at 60 Hz (the SRAM it presents already holds a video mode). Not a rendering difference; the game's 50 Hz mode is not reachable in the recomp.
