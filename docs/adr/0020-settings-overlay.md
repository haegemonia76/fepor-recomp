# 0020 In-game settings overlay

Status: accepted (implements ticket #20, replaces the F2/F3/F4 hotkeys of ADR 0016)

**What**
- All player-facing options live in an overlay drawn over the game window: Video (frame multiplier, internal resolution, picture shape, fullscreen, vsync), Audio (master volume, output device), Controls (per-action rebinding for keyboard and gamepad, button-name family, stick dead zone, restore defaults), Memory card (slot A status, saves, export as `.gci`), Help and Quit. It is opened with F1 or the gamepad's Guide / Back button and closed with the same, Esc or B. Page Up/Down or LB/RB switch pages; navigation is arrows + Enter, D-pad / left stick + A, or the mouse.
- While it is open the game's pad reads neutral (`Controls::set_suspended`); inputs being captured as a binding bypass the menu and go to `Controls`.

**How**
- `crates/overlay` uses egui (`egui` core only, default fonts) for layout and our own wgpu painter (`paint.rs`, a small port of egui-wgpu's renderer) because `egui-wgpu` needs a newer wgpu than `fepor-video`. Events are converted from winit by hand (`shared.rs`): the window thread and the gamepad thread push into `Shared`, the render thread owns `Overlay`, runs the UI once per presented image and paints it as a last render pass over the swapchain (`Presenter::show`). Held pad directions repeat like a keyboard.
- Settings: `fepor_core::settings` (`<data>/settings.toml`: `[video] frame_multiplier, resolution, aspect, fullscreen`, `[audio] volume`). A `SettingsHandle` is shared by the overlay (writer, saves on change), the renderer and the audio sink (readers, poll `generation()`). `FEPOR_FPS_MULT`, `FEPOR_RES`, `FEPOR_ASPECT` still override the file for one run and are never saved.
- Live application: frame multiplier (drops the recorded frames, switches the present mode), aspect, fullscreen and volume apply at once; resolution rebuilds the render targets between frames (`Renderer::apply_settings`). The volume gain is the slider squared.
- Memory cards: the page shows the card and exports its saves. Saves cannot be imported into a card the running game has open, so the "Choose .gci files..." button (native file chooser from `rfd`, run on its own thread) copies the chosen files into `<data>/imports` after checking their size (a 0x40-byte entry plus whole 8 KiB blocks), and they are imported into slot A at the next start (renamed `.gci.imported`; one the card cannot take, because it already holds that name or is full, is renamed `.gci.failed` and listed in red). The card must already be formatted by the game. Pending and failed files are listed with a Remove button.
- Display and device: the Video page shows the game's measured frame rate against the display's refresh rate (more images per second than the display refreshes are never seen: on a 60 Hz screen a frame multiplier only helps scenes the game draws at 30 frames/s); the vsync option picks the present mode (`Presenter::set_present`: Fifo when on and not interpolating, newest-image-wins when interpolating, immediate when off). The Audio page lists SDL playback devices (refreshed every 2 s by the audio thread) and reopens the stream on the chosen one, falling back to the system default when it is gone (`audio.device` in `settings.toml`).
- A Quit page ends the process at once (no confirmation).
- Statistics HUD (F2 cycles off / frame rate only / full; Video page; `FEPOR_STATS=fps|1`; `video.stats`; the overlay text size follows the window height, or `video.overlay_scale`): drawn in the top-left corner without the settings panel. The renderer publishes a `StatsSnapshot` four times a second: game frames/s, images shown/s (`Presenter::shown`), display Hz, a 120-frame frame-interval graph with average / p99 / worst, the guest thread's time per second in draw/copy events and in interpolated images, draws per frame, process CPU, memory and the busiest threads (Linux `/proc`; the guest thread is named `guest`), GPU utilisation (AMD `gpu_busy_percent` in sysfs, matched to the wgpu adapter by PCI ids) and submission-to-completion latency of GPU work (`on_submitted_work_done`; wgpu has no portable GPU timer), and the AX frames / AI buffers per second the audio side produces (`fepor_core::stats`, 200 = real time). Colours turn yellow/red on spikes, a busy guest thread or audio below real time.
- Look (`theme.rs`, ticket #25): after the game's menus, drawn procedurally so that nothing from the game is copied: a dark green gradient panel framed in thin gold with squared corner brackets and diamonds, tabs and buttons as green bars with gold edges (lit gold when selected or hovered), gold captions and sliders, cream text. The font is Marcellus (SIL Open Font License 1.1, `crates/overlay/assets/Marcellus-Regular.ttf` and `OFL.txt`), with egui's own fonts as fallback and Hack for the statistics. The tabs wrap on narrow windows. The statistics panel uses the same bar colour and gold edge.
- Controls page (`pad.rs`): a drawing of the controller of the chosen family. The silhouettes are traced from photographs (`outlines.rs`, made with `tools/trace-outline.py`: GameCube, Xbox Series and DualSense, all from Wikimedia Commons under CC BY-SA; the Switch Pro uses the Xbox outline) and every button sits where it is on the photograph; shell colours, stick wells, D-pads and touchpad are drawn over them, buttons are the generated icons of ADR 0021. Only the outline numbers are kept, never a photograph. Xbox, Nintendo and PlayStation: every physical input (face buttons, shoulders, triggers, back/start, the four directions and the press of each stick, the four D-pad arms) is a spot you click; the GameCube button it is bound to is written beside it in gold; a list of the GameCube buttons then lets you bind it (`Controls::assign`, the button's earlier input is released) or choose "Nothing" (`Controls::unassign`). GameCube: the GameCube controller with its own layout; a click on a GameCube button starts a capture (`Controls::rebind`) of the next gamepad input, and the input now bound is written beside the button. The keyboard keeps the list with Rebind buttons.
- Language page (ticket #21): the text language (English, Deutsch, Français, Español, Italiano) is `game.language` in `settings.toml` and `FEPOR_LANG` for one run. The game reads it from the console's SRAM language byte (offset 0x12, `OS_LANG_*`) when it starts, so `Hw::set_language` writes it, with valid checksums, before the boot and a change in the overlay applies at the next start. Checked on the title screen and the memory card prompts in French and German. The EU disc has no per-language audio (voices, MusyX bank, BGM streams and THP movies are single-language; subtitles come from the text set), so there is no audio-language option; one would need a second disc (GFEJ01/GFEE01) mapped over the first, which is not planned.

**Not done (tickets)**
- Matching the game's own menu art closer (scrollwork on the bars, the dragon cursor): the theme only borrows the palette and layout.
- The overlay is not drawn into interpolated frame dumps (`frame_N_tXX.png`): those dumps are a developer check of the interpolation, not something the player sees.
