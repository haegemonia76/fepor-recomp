# 0047 Bug report bundle

Status: accepted (implements ticket #47)

**What**
- `fepor-recomp bug-report [--out file.zip]`, the Help page of the overlay ("Make bug report") and the launcher GUI's "Bug report" button write one zip to `<data>/bug-reports/fepor-bug-report-<unix time>.zip` and show its path. All three call `fepor_core::bugreport`. Better too much than too little, as long as it is anonymised.
- Files: `report.txt`, `settings.toml`, `input.toml` (controller profiles by GUID: not personal), `cheats.toml`, `playtime.toml` (when it exists), `mods/mods.toml` and the `mod.toml` of each enabled mod (not its files), the logs (`logs/fepor-game.log`, `fepor-game.prev.log`, the launcher's rotated ones, each cut to its last 512 KiB), `logs/session.toml`, `crash.txt` (the `fepor: fatal:` / watchdog / panic block of the logs, with registers and backtrace) and `screenshot.png`.
- `report.txt` holds: the `anonymised:` list (what was stripped), build, engine, game ID, `FEPOR_TRACE`; OS, kernel, CPU, RAM, cores; the command line and every `FEPOR_*` / `RECOMPLAUNCHER_*` variable; game ID, version, region, kind and size of the copy; GPU adapter, backend, driver strings and wgpu limits; SDL version, audio driver and playback devices; controllers (name, GUID, player index); and, from a report made in the running game, the renderer (frames, frame rate, frame multiplier and resolution in effect, window and display size and refresh rate, swapchain, settings in effect, the HUD's last snapshot when it was on), the guest machine (retraces, thread counts per state, audio counters), the patch sets by source with patch and byte counts, the JIT's function counts and the time the game has run. Memory cards appear as text only: file, size, formatted, free blocks, save names and block counts (what `card-info` prints); card backups as names and sizes.
- Screenshot: a report made in the running game contains the frame on screen at that moment (read from the renderer like a frame dump, without the overlay); otherwise the newest `.png` of `<data>/screenshots`, if any.
- Never in it: card images (`.raw`), saves (`.gci`), `disc/`, game files, generated code, `cheats/` definitions, anything of a mod but its manifest. `is_excluded` rejects these folders and file types for every entry, whatever collected it.

**Anonymisation** (`fepor_core::anonymise`, the only place that decides): the data folder becomes `<data>`, the folder of the disc image `<disc folder>` (the report keeps no more than "disc image .ext, N bytes"), the home directory `~`, e-mail addresses `<email>`, the user name and host name as whole words (never inside another word: `bobby` stays for `bob`) `<user>` / `<host>`, the machine id `<machine id>`, MAC addresses `<mac>`, IP addresses `<ip>` (a version such as `1.2.3.4.5` is not one), and every other absolute path (Linux, macOS `/Users/...`, Windows `C:\Users\...`, UNC, TOML-escaped `\\`) `<path>`. `report.txt` starts with the list of kinds that were found.

**How**
- The game keeps `<data>/logs/session.toml` (`bugreport::init`, `update_session`, `note(name, text)`): build, engine, trace, game ID, disc folder and text blocks published by the crates at start (environment, arguments, game, GPU, audio, controllers). The CLI and the GUI read it, so a report made after the game ended is as complete as one made in it; state that changes goes to `create` as `Extra` from the process that runs it: the overlay asks (`Shared::request_report`), the renderer makes the report at its next frame (picture, renderer state) and adds the sections of the game's hook (`Shared::set_report_hook`: runtime and JIT state).
- The game's own log (`fepor_core::applog`, Unix): stderr is mirrored into `<data>/logs/fepor-game.log`, the previous run's log is kept as `fepor-game.prev.log`, and a log reaching 16 MiB starts over (its end is what stays). `process::exit` after a crash message goes through `applog::exit`, which waits until the mirror copied the last lines. `fepor-recomp run` keeps writing the log itself (rotation `.1.log`...) and tells the game with `FEPOR_LOGGED=1`, so nothing is logged twice.
- `FEPOR_BUG_REPORT=<frame>` makes the renderer request a report at that guest frame (headless checks).

**Limits**
- Windows and macOS were not run: the game keeps no log file of its own on Windows (`applog` needs `dup2`; `fepor-recomp run` still writes it), CPU/RAM/kernel are read from `/proc` and show only the OS name and core count elsewhere.
- The anonymiser knows the user name, host name, machine id and home of the machine that makes the report, so text from a log of another machine is only stripped by pattern (paths, addresses, e-mail). A path with spaces outside the data folder, disc folder and home is cut at the first space.
- There is no save state feature yet, so no "save state loaded" line; the thread table is read from guest memory while the guest runs (counts may be off by one in a switch).
