# Tools

Reusable helpers. Extend these (or the `fepor-recomp` subcommands) instead of writing one-off scripts.

| Tool | Purpose |
| --- | --- |
| `fepor-recomp extract` | Extract `sys/` and `files/` from the disc image into `--data`. |
| `fepor-recomp analyze` | Function starts, jump tables and warnings; report in `<data>/analysis.txt`. |
| `fepor-recomp generate` | Generate the C++ project into `<data>/generated`. |
| `fepor-recomp prepare` | Generate and build; the RecompLauncher setup step (`progress` lines, stable exit codes). |
| `fepor-recomp run --data <dir>` | Start the built game as RecompLauncher's Play does: log in `<data>/logs/fepor-game.log`, the game's exit code. Reads `RECOMPLAUNCHER_MODE` and `RECOMPLAUNCHER_PAD` (through the game). |
| `fepor-recomp disasm --addr 0x80003154 --count 16` | Disassemble guest code from main.dol. |
| `fepor-recomp opcodes` | Instruction histogram of main.dol (what the lifter must cover). |
| `fepor-recomp find --op Rfi` | Every occurrence of an opcode with its function (locating SDK internals). |
| `fepor-recomp find --pointers 0x8026b2a8` | Data words and `lis`+`addi/ori` pairs that reference an address (function pointers). |
| `fepor-recomp card-info <image.raw>` | Memory card image check: header/directory/BAT checksums and the saves on the card. |
| `fepor-recomp card-import <card.raw> <save.gci>` / `card-export <card.raw> <out.gci> [--name N]` | Move saves between a raw card image and Dolphin's `.gci` files (a save exported from a card is byte-identical to the one Dolphin wrote). |
| Memory card backups | The card is copied to `<data>/memcards/backups/<card>.<unix time>.raw` at each start and every 5 min while changed; the last `game.card_backups` (default 5, 0 = off) are kept; restore from the overlay Memory card page (applied at the next start). See ADR 0020. |
| `tools/dolphin-run.sh --iso <disc> [--card <raw>] [--log-video] -- wait:12 press:A mash:START:40 shot:out.png ...` | Run the game in Dolphin (reference emulator) in an isolated user dir, driven through its pipe controller, with screenshots: compare saves, memory cards and frames with the recomp. `--log-video` writes Dolphin's video log to `<user>/Logs/dolphin.log`; `DOLPHIN_ARGS` adds options. It opens a Dolphin window on the desktop (even with `QT_QPA_PLATFORM=offscreen`), so do not run it while someone is playing. Needs `dolphin-emu` and KDE's `spectacle`. |
| `tools/compare-frames.py --recomp DIR --dolphin DIR [--first N] [--out DIR]` | Compare a recomp run's frames (`FEPOR_DUMP_FRAMES`, one per frame) with Dolphin's (`dolphin-run.sh --dump-frames`): matches them by dynamic time warping, prints the PSNR per frame and writes the worst side by side with their difference; exit 1 under `--min-psnr`. Needs `.venv-tools` (numpy, Pillow); an AVI needs ffmpeg. Workflow in ADR 0008. |
| `tools/regress.py record\|check\|shots --data DIR [--card RAW]` | Frame regression test: plays two scripted runs headless (new game; the player's save to the victory-terms menu), then checks that each known screen (warning, title, difficulty, prologue field, chapter list, the tactical map of the victory menu) appears in every run, by PSNR on a crop. `record` stores the references in `.cache/regress` (not committed: they are game pictures); `shots` dumps frames to choose scenes; `--runs N` repeats because timing-dependent bugs show in some runs only. Needs `.venv-tools`, a prepared data folder, and for the save scenes a copy of a card with a chapter 1 save. Takes about 4 minutes. |
| `fepor-recomp ls` | Disc files with offsets and sizes (match `FEPOR_TRACE=di` reads, which print offset/4). |
| `cargo build --release -p fepor-game` / `fepor-recomp prepare` / `fepor-recomp run` | The game as players get it (ADR 0024): the code is compiled in process (`crates/jit`), `prepare` is the analysis and the copy of the game data (no clang, CMake or Ninja), `run` starts it. `FEPOR_TRACE=jit` prints compile times, `FEPOR_JIT_DUMP=<hex function start>` the Cranelift IR of one function, `FEPOR_FIRST_SEEN=<file>` (with `FEPOR_WATCHDOG=s FEPOR_TRACE=calls`) every function in the order it first ran. The C++ backend for debugging the compiler: `fepor-recomp prepare --cpp` then `cargo build --release -p fepor-game --no-default-features --features cpp` with `FEPOR_GENERATED_DIR` (what `tools/dev-run.sh` does). |
| `FEPOR_TRACE=calls FEPOR_WATCH_MEM=<hex address>` | Print each change of one guest memory word with the last 8 function entries (the writer is among them), and `FEPOR_WATCH=<hex function>,...` prints the arguments and `r2`/`r13` of those functions: how the GX state of a bad draw was set up. |
| `tools/dev-run.sh <disc>` | Development loop: generate (with call tracing), build, link with the Rust runtime (`crates/game`), run. Env: `FEPOR_TRACE=hw,calls`, `FEPOR_HW_LIMIT=n`, `FEPOR_WATCHDOG=secs`, `SKIP_PREPARE=1`. Video/input env: `FEPOR_HEADLESS=1` (no window; required for dumps in CI), `FEPOR_DUMP_AUDIO=file.wav`, `FEPOR_NO_AUDIO=1`, `FEPOR_MEMCARD_A=<file|none>`, `FEPOR_DUMP_FRAMES=dir`, `FEPOR_DUMP_EVERY=n`, `FEPOR_DUMP_TEXTURES=dir`, `FEPOR_PAD=A@400+8,...`, `FEPOR_NO_VIDEO=1`, `FEPOR_OVERLAY=video|audio|language|controls|card|help|quit`, `FEPOR_LANG=en|de|fr|es|it` (text language for this run) (settings overlay open at start; frame dumps then include it), `FEPOR_STATS=fps|1` (statistics HUD: frame rate only / full), `FEPOR_RES=n` (internal resolution 1..4), `FEPOR_ASPECT=fit|stretch|16:9|21:9`, `FEPOR_FPS_MULT=n` (n images per guest frame, interpolated; with `FEPOR_DUMP_FRAMES` the interpolated images are dumped as `frame_N_tXX.png`; `FEPOR_RES`, `FEPOR_ASPECT` and `FEPOR_FPS_MULT` override `<data>/settings.toml` for one run), `FEPOR_TRACE=gx,gxdraw,gxhash,gxstats,dsp,di,irq,vi,ax,input,audio`, `FEPOR_AX_EVERY=n`, `FEPOR_AX_DUMP_VOICE=<hex PB addr>`, `FEPOR_WATCH=<hex addrs>` (log arguments on entry), `FEPOR_RECENT=1` (long call history in crash reports). `FEPOR_TRACE=calls` also prints a histogram of the hottest functions every 16M entries. |
| `tools/audio-check.py file.wav [--bands]` | Find clicks/crackle per second in a `FEPOR_DUMP_AUDIO` WAV, or print energy per frequency band to compare two dumps. Needs `.venv-tools`. |
| `tools/trace-outline.py PHOTO --mode alpha\|white\|dark\|border\|saturated --name NAME` | Trace the silhouette of a controller photo into a Rust constant (outline only, normalised to 1.0 wide; `--grid out.png` writes the cropped photo with a labelled grid to read button positions from). Used for `crates/overlay/src/outlines.rs`. Needs `.venv-tools` (numpy, Pillow) and `potrace`. |
| `tools/vectors.sh [out]` | Regenerate `crates/ppc-lift/tests/vectors.bin` with Unicorn (`gen_vectors.py`, ADR 0008). Output is deterministic. |
| `tools/validate-profile.sh [file]` | Validate `packaging/recomplauncher.json` against RecompLauncher's schema. |
| `tools/package-release.sh <version> <windows\|linux\|macos> <x64\|arm64> <bin-dir> [out-dir]` | One release archive (ADR 0023): `fepor-recomp`, `fepor-game`, the profile stamped with the version, the licence. Needs `jq`, and `7z` for the Windows zip. Used by `.github/workflows/release.yml`. |
| `tools/venv.sh` | Sourced by the scripts above: creates `.venv-tools` from `tools/requirements.txt`. |

All `fepor-recomp` commands take `--disc/--game`, `--output/--data` (or `RECOMPLAUNCHER_DATA`), `--config` and `--no-verify`.
